# Dashboard design system

The existing app uses React 19, TypeScript, Vite, custom CSS, Lucide icons and local browser persistence. The official shadcn CLI initialized this project in place with `--base radix --preset nova --rtl --no-monorepo --yes`; `components.json` records the `radix-nova` style and RTL transformations. The CLI added Button, Input, Select, Dialog, Card, Tabs, Badge, Table, Sidebar, Calendar, Progress, Skeleton, Dropdown Menu, Tooltip and Direction, plus Sidebar dependencies. Existing legacy components were inspected and retained.

## Scope and maintenance

- `src/Dashboard.tsx` uses the existing `report`, `dateRange`, `budgetUsage`, visibility and formatting functions. Persistence updates only the existing per-viewer dashboard card preferences. No ledger, API, route or migration behavior is introduced.
- `src/BudgetReporting.tsx` re-exports the new Dashboard; other reporting and budget pages retain their existing UI.
- `src/components/ui` contains CLI-generated official component source. Customize it locally. `src/lib/utils.ts` is generated by the CLI; the current preset imports `cn` directly.
- `src/design-system.css` maps Tailwind utilities to semantic variables. Global Tailwind Preflight and CLI-generated body/reset rules are intentionally omitted to preserve other pages. Utilities are unlayered so legacy unlayered CSS cannot override new component utilities. Tokens live in `src/dashboard-tokens.css`, scoped to `.ds-dashboard` and `.ds-portal` (Radix content renders outside the Dashboard DOM subtree).
- DirectionProvider wraps the Dashboard. Portal surfaces explicitly receive direction where their APIs support it; DropdownMenu receives direction on its root. Sidebar is used for card customization with `side="right"`, preserving the existing app navigation and routes.
- Light starting tokens: primary `#2563EB`, success `#16A34A`, destructive `#DC2626`, warning `#D97706`, background `#F8FAFC`, foreground `#0F172A`, border `#E2E8F0`. Dark tokens follow the existing `html[data-theme="dark"]` setting. Warnings retain text and status/alert semantics.
- Typography tokens define heading, body, label, caption and amount sizes. All app typography uses the already bundled Vazirmatn fonts (400, 500, 600, 700, plus existing 800) with system fallback only if unavailable. Font provenance: the official Vazirmatn project, identified in `public/fonts/OFL.txt`; assets remain offline-capable. The CLI's Geist font was removed. Financial amounts use isolated bidi text and tabular numerals.
- Persian dates and numeric formatting continue respecting existing user preferences rather than silently replacing them. Calendar is Jalali with Persian numerals; the HTML language is `fa-IR`. Calendar selection only displays scheduled commitments.
- Calendar uses `react-day-picker` 9: the CLI installed 10, whose exports no longer include the documented `/persian` entry point. Types/utilities remain imported from the main entry point, and only DayPicker comes from `/persian`. Its custom month formatter also uses the Persian calendar.
- Progress has a local RTL transform and forwards its numeric value to Radix for accessible progress values. Raw budget percentages and overage amounts remain visible even when the visual bar reaches 100%.
- `DashboardSkeleton` is available for a future asynchronous loading boundary; this app currently loads local data synchronously, so it does not display an artificial loading state.

## Verification

`npm run typecheck`, `npm run build`, and `npm test` passed. The test command includes 101 finance/reporting/persistence/UI tests and 3 exchange-rate adapter tests. Browser verification covered mobile and desktop layouts, RTL, computed Vazirmatn font, horizontal overflow, customization search, dialog close, and Persian calendar rendering. No browser warnings/errors were observed. No transactions were posted during UI checks.

Windows sandbox restrictions initially blocked npm DNS, Vite realpath and local preview listening; authorized execution outside that sandbox completed installation, build and preview. Build warns about ignored React `use client` directives and the single bundle exceeding 500 kB (approximately 816 kB / 243 kB gzip). These are non-fatal; code splitting can be a separate follow-up.

`npm audit --omit=dev` reports zero vulnerabilities. Full audit reports seven high-severity development dependency entries rooted in the latest official shadcn CLI's glob/morph dependencies. The vulnerable transitive `source-map-js` was updated. No forced downgrade to the obsolete CLI was applied.
