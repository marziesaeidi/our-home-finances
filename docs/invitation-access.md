# درخواست عضویت

مالک در «فضای مشترک» لینک جدید می‌سازد؛ کلید بررسی درخواست‌ها در همان مرورگر مالک نگهداری می‌شود. دعوت‌شونده نام و ایمیل را وارد می‌کند. ارسال فرم فقط یک درخواست در SQLite ایجاد می‌کند و داده مالی یا عضویت برنمی‌گرداند. لینک برای یک درخواست قابل استفاده است.

در زمان باز بودن اپ مالک، درخواست‌های جدید هر ۱۰ ثانیه بررسی می‌شوند. اعلان داخل اپ و فهرست درخواست‌ها در «یادآوری‌ها» و «فضای مشترک» نمایش داده می‌شوند. مالک می‌تواند درخواست را تأیید یا رد کند. تأیید، عضو با دسترسی ثبت و ویرایش می‌سازد؛ رد کردن عضوی ایجاد نمی‌کند. تراکنش دیتابیس، تغییر وضعیت و ایجاد عضو را با هم ذخیره می‌کند.

صفحه درخواست وضعیت را هر ۱۰ ثانیه بررسی می‌کند. پس از تأیید، دکمه ورود فعال می‌شود. شناسه محرمانه پیگیری در sessionStorage همان تب نگهداری می‌شود؛ تب باید تا ورود باز بماند. ورود، مانند مسیر قبلی، یک نسخه محلی از داده‌ها می‌سازد؛ همگام‌سازی مالی خودکار هنوز وجود ندارد.

پیش‌نمایش مستقل طراحی: `/#invite-preview`. ارسال فرم در پیش‌نمایش فقط حالت انتظار را نمایش می‌دهد و چیزی به دیتابیس نمی‌فرستد.

این تغییر جایگزین احراز هویت عمومی نیست. ایمیل در این مرحله فقط برای معرفی است و مالکیت آن بررسی نمی‌شود. API قدیمی خواندن و نوشتن snapshot و ساخت دعوت همچنان احراز هویت کاربر ندارد؛ قبل از انتشار اینترنتی باید ورود امن، کنترل دسترسی همه مسیرهای سرور و تأیید ایمیل تکمیل شود. اعلان فعلی داخل اپ است و اعلان پس‌زمینه یا ایمیل ارسال نمی‌شود.

برای اجرای نسخه جدید، برنامه را build و سرویس `npm run database` را با کد جدید اجرا کنید. جدول‌های جدید بدون تغییر snapshotهای مالی ساخته می‌شوند.
