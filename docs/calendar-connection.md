# اتصال تقویم

در «مدیریت ← فضای مشترک»، مالک ایمیل تقویم را ذخیره می‌کند. هر عضو با دکمه اتصال به Google Calendar حساب مقصد را در پنجره گوگل انتخاب و مجوز را تأیید می‌کند. ایمیل ذخیره‌شده صرفاً پیشنهاد ورود است. برای فضای مشترک بهتر است فقط یک دستگاه/عضو مسئول ارسال به تقویم مشترک باشد تا موعد مشترک از طرف چند عضو تکرار نشود.

## راه‌اندازی

1. در Google Cloud یک پروژه و OAuth consent screen بسازید و Google Calendar API را فعال کنید.
2. یک OAuth Client از نوع Web application بسازید؛ origin دقیق برنامه (با پروتکل و پورت) را در Authorized JavaScript origins قرار دهید. برای استفاده عمومی HTTPS لازم است. حساب‌های آزمایش را در حالت Testing اضافه کنید؛ انتشار عمومی ممکن است نیازمند تأیید دسترسی گوگل باشد.
3. در فایل `.env.local` مقدار `VITE_GOOGLE_CLIENT_ID=YOUR_CLIENT_ID.apps.googleusercontent.com` را ثبت و برنامه را دوباره build کنید. این شناسه عمومی است؛ client secret در فرانت‌اند قرار ندهید.
4. ایمیل را ذخیره، اتصال را تأیید و یک موعد آزمایشی با یادآوری بسازید. تغییر موعد و تسویه آن را بررسی کنید؛ رویداد باید تغییر یا حذف شود. اعلان تقویم گوشی را نیز فعال کنید.

مجوز `calendar.events` امکان مدیریت رویدادها را می‌دهد؛ برنامه تنها رویدادهای دارای نشان اختصاصی فضای مالی و عضو را تغییر می‌دهد. عنوان، تاریخ و فاصله یادآوری ارسال می‌شوند. توکن فقط در حافظه است و در پشتیبان یا localStorage ذخیره نمی‌شود. انقضای مجوز یا بارگذاری مجدد نیازمند اتصال دوباره است.

همگام‌سازی با فاصله کوتاه پس از تغییر داده، هنگام باز بودن اپ انجام می‌شود؛ اجرای پس‌زمینه یا refresh token سرور وجود ندارد. اعلان‌های رویدادهای ثبت‌شده پس از بسته شدن اپ توسط تقویم ارائه می‌شوند. موعدهای دوره‌ای تا یک سال آینده ارسال می‌شوند. حداکثر پنج اعلان در محدوده ۲۸ روز پیش از موعد، ساعت ۹ صبح تهران ثبت می‌شود. قطع اتصال رویدادهای قبلی را حذف نمی‌کند؛ در صورت نیاز از خود تقویم حذفشان کنید. تقویم Apple/Outlook اتصال مستقیم ندارد؛ حساب گوگل مقصد باید در تقویم دستگاه فعال باشد.
